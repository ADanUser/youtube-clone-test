# План разработки

Текущий этап: последовательная реализация по утверждённой архитектуре. `[x]` означает выполненный критерий, `[ ]` — предстоящую работу. После каждого шага агент обновляет этот файл, проверяет результат, создаёт атомарный коммит и сообщает терминальные команды.

- [x] **2. Создать и проверить документы проектирования.** В корне находятся AGENTS.md, ARCHITECTURE.md и TODO.md; описаны поток видео, БД, роли, приватность, эксплуатация и проверки.
- [x] **3. Инициализировать Git и создать первый коммит.** Ветка `main`, коммит `docs: define architecture and agent workflow`, в коммите только три документа; после коммита рабочее дерево чистое.
- [x] **4. Создать каркас и конфигурацию.** Модули приложения и worker, типизированные настройки, `.gitignore`, безопасный `.env.example`, фиксированные зависимости, Ruff и базовые проверки; описаны реальные команды локального запуска и тестов.
- [x] **5. Поднять инфраструктуру Compose.** PostgreSQL, Garage, идемпотентный `garage-init` (layout assign/apply, бакет, ключи, права, защищённая передача секретов), сервис миграций, приложение, worker и Nginx. Для этой стадии достаточно базовой миграции без предметных таблиц. Проверены пустые тома, повторный запуск, частичная инициализация и блокирование приложения при ошибке init; ручные CLI-команды не нужны.
- [x] **6. Создать предметную схему БД.** Все таблицы и связи из архитектуры, CHECK/UNIQUE/FK, индексы, `pg_trgm`, миграции с пустой и предыдущей схемы; ограничения проверены на PostgreSQL.
- [x] **7. Реализовать аккаунты и каналы.** Регистрация, вход/выход, серверные сессии, роли, блокировка, профиль канала, CSRF и ограничения попыток входа; пользователь не может назначить себе роль.
- [x] **8. Реализовать загрузку.** Черновик с метаданными и приватностью по умолчанию; потоковый octet-stream, лимит фактических байтов, резерв временного диска и слоты, закрытое S3 с ограниченными multipart-буферами. Проверены владелец/CSRF, конкурентные запросы, отмена, таймауты, сбои диска/S3/коммита и повторная попытка; asset и transcode-job фиксируются атомарно. Страница `/upload` показывает XHR-прогресс и отдельное ожидание обработки. Проверки PostgreSQL + Garage, Ruff, JavaScript и HTTP через Nginx; визуальная браузерная проверка недоступна (браузерный хост не запущен). Восстановление после аварийного завершения процесса и очистка сирот реализованы в пункте 9.
- [x] **9. Реализовать обработку.** Очередь PostgreSQL с SKIP LOCKED, арендой, heartbeat и тремя попытками; FFprobe/FFmpeg создаёт MP4 H.264/AAC с faststart и JPEG в закрытом S3. Публикация обоих asset, метаданных и ready атомарна и защищена token/сроком аренды/upload_id. Реализованы восстановление после остановки, очистка загрузок/multipart/сирот старше 24 часов и идемпотентный delete-job. Ограничены CPU/RAM/диск/время, сеть декодера запрещена seccomp. Проверены 71 тест полного набора и дополнительный сквозной API → S3 → FFmpeg → ready; 9 медиа-тестов также прошли с ограничениями контейнера. Ruff и проверка diff успешны.
- [x] **10. Реализовать просмотр и приватность.** GET/HEAD, одиночные HTTP Range 206/416 и If-Range, защищённые превью и метаданные, HTML5-плеер и выдача/отзыв доступа. Проверена матрица ролей: private доступно только владельцу/получателю grant, hidden не воспроизводится никем; права проверяются до S3 на каждом запросе. Подтверждены перемотка настоящего MP4 через HTTP-декодер, ограниченное чтение и закрытие соединения при отмене. Общий прогон: 99 тестов прошли; единственный сбой подготовки cookie тестового клиента исправлен, целевой повтор — 1 passed. Ruff, форматирование, JavaScript и diff проверены. Визуальная проверка HTML5-плеера в браузере остаётся в пункте 15.
- [x] **11. Создать пользовательские экраны.** Реализованы общие адаптивные Jinja2 + TailwindCSS-шаблоны в тёмном YouTube-подобном стиле: главная, просмотр, канал, поиск по названию, загрузка с прогрессом, вход/регистрация и студия управления собственными видео. HTML использует общие сервисы доступа; добавлены серверная пагинация, безопасное редактирование метаданных через API с CSRF, пустые состояния и HTML-ошибки. Ruff, компиляция шаблонов, JavaScript и 34 доступных теста прошли; полный интеграционный прогон PostgreSQL + Garage дал 100 passed до исправления двух новых тестов, их повторный прогон — 2 passed. Автоматическая визуальная проверка недоступна: browser access host не запущен.
- [x] **12. Добавить социальные функции.** Реализованы идемпотентные лайки, комментарии с удалением автором, подписки без самоподписки и публичные/приватные плейлисты с добавлением, удалением и сохранением порядка видео. Все мутации защищены сессией и CSRF, лайки и комментарии требуют доступа к видео. Составные PK обеспечивают один лайк и одну подписку; приватное видео нельзя добавить в чужой плейлист, а выдача плейлиста повторно фильтрует каждый элемент по правилам просмотра. Кнопки и формы подключены к экранам просмотра, канала и новым страницам плейлистов. Ruff, форматирование, шаблоны, JavaScript и 34 доступных теста прошли; целевые PostgreSQL-тесты — 4 passed. Полный интеграционный прогон дал 103 passed и один нестабильный тест изоляции пагинации, после исправления его целевой повтор — 1 passed.
- [x] **13. Добавить модерацию.** Добавлены жалобы только при доступе к видео, отдельная панель модератора, транзакционное скрытие/восстановление с обязательной причиной и append-only аудитом, отклонение жалоб и админское управление ролями/блокировками. Блокировка отзывает сессии, защита последнего активного администратора сохранена. Панель не раскрывает title/description чужого private-видео, а watch/metadata/thumbnail/stream для модератора без grant возвращают 404. Ruff, форматирование, Python/JavaScript и 34 доступных теста прошли; целевые PostgreSQL-тесты — 3 passed, полный PostgreSQL/Garage/FFmpeg-прогон — 106 passed.

Добавить демо-данные.** Идемпотентный seed создаёт пользователей всех ролей, каналы, готовые публичные/приватные/скрытые видео, разрешения, комментарии, лайки, подписки, плейлисты и жалобы.
