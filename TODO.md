# План разработки

Текущий этап: последовательная реализация по утверждённой архитектуре. `[x]` означает выполненный критерий, `[ ]` — предстоящую работу. После каждого шага агент обновляет этот файл, проверяет результат, создаёт атомарный коммит и сообщает терминальные команды.

- [x] **1. Изучить ТЗ и зафиксировать решения.** Прочитан `TZ-YouTube-kopiya.md` из Downloads; согласованы Jinja2 + HTMX, MP4 + HTTP Range, автоматические коммиты агента и автоинициализация Garage. Архитектура покрывает восемь критериев ТЗ.
- [x] **2. Создать и проверить документы проектирования.** В корне находятся AGENTS.md, ARCHITECTURE.md и TODO.md; описаны поток видео, БД, роли, приватность, эксплуатация и проверки.
- [x] **3. Инициализировать Git и создать первый коммит.** Ветка `main`, коммит `docs: define architecture and agent workflow`, в коммите только три документа; после коммита рабочее дерево чистое.
- [x] **4. Создать каркас и конфигурацию.** Модули приложения и worker, типизированные настройки, `.gitignore`, безопасный `.env.example`, фиксированные зависимости, Ruff и базовые проверки; описаны реальные команды локального запуска и тестов.
- [x] **5. Поднять инфраструктуру Compose.** PostgreSQL, Garage, идемпотентный `garage-init` (layout assign/apply, бакет, ключи, права, защищённая передача секретов), сервис миграций, приложение, worker и Nginx. Для этой стадии достаточно базовой миграции без предметных таблиц. Проверены пустые тома, повторный запуск, частичная инициализация и блокирование приложения при ошибке init; ручные CLI-команды не нужны.
- [x] **6. Создать предметную схему БД.** Все таблицы и связи из архитектуры, CHECK/UNIQUE/FK, индексы, `pg_trgm`, миграции с пустой и предыдущей схемы; ограничения проверены на PostgreSQL.
- [x] **7. Реализовать аккаунты и каналы.** Регистрация, вход/выход, серверные сессии, роли, блокировка, профиль канала, CSRF и ограничения попыток входа; пользователь не может назначить себе роль.
- [ ] **8. Реализовать загрузку.** Прогресс, метаданные, лимиты байтов и временного диска, закрытое S3, проверка владельца, обработка прерывания; полный файл не помещается в RAM.
- [ ] **9. Реализовать обработку.** Очередь PostgreSQL, FFprobe/FFmpeg, MP4 и превью, аренда и повторы заданий, восстановление после остановки, очистка незавершённых загрузок и объектов.
- [ ] **10. Реализовать просмотр и приватность.** GET/HEAD, HTTP Range, перемотка, защищённые превью, выдача/отзыв доступа; проверена матрица ролей, скрытые видео недоступны для воспроизведения.
- [ ] **11. Создать пользовательские экраны.** Главная, просмотр, канал, поиск по названию, загрузка, вход/регистрация, управление собственными видео; расположение элементов в стиле YouTube, адаптивность, пустые состояния и ошибки, пагинация.
- [ ] **12. Добавить социальные функции.** Лайки, комментарии, подписки, плейлисты и порядок видео; уникальность действий и фильтрация приватных материалов проверены.
- [ ] **13. Добавить модерацию.** Экран жалоб, скрытие/восстановление с причиной и аудитом, управление ролями и блокировками; проверено отсутствие обхода приватности через административные маршруты.
- [ ] **14. Добавить демо-данные.** Идемпотентный seed создаёт пользователей всех ролей, каналы, готовые публичные/приватные/скрытые видео, разрешения, комментарии, лайки, подписки, плейлисты и жалобы. Тестовые ролики генерируются локально, seed ждёт завершения обработки и не сбрасывает существующие пароли.
- [ ] **15. Завершить автотесты.** Unit, интеграционные PostgreSQL + Garage и браузерные тесты; проверены основной сценарий, матрица доступа, Range, CSRF/XSS/IDOR, ограничения загрузки, повторы и отказы worker. Тесты добавляются по мере реализации; этот пункт завершает покрытие.
- [ ] **16. Подготовить деплой и эксплуатацию.** `sudo bash scripts/deploy.sh` устанавливает зависимости, генерирует секреты, поднимает Compose, инициализирует Garage, применяет миграции, запускает seed и проверяет готовность. Документированы HTTP для теста по IP, HTTPS для домена, логи, бэкап и восстановление.
- [ ] **17. Проверить чистую Ubuntu 24.04 LTS.** На отдельной чистой VM одна команда без ручной настройки приводит к рабочему сценарию регистрации → загрузки → просмотра → лайка → комментария; повторный деплой сохраняет данные и ключи. Проверены частичный сбой init и восстановление бэкапа.
- [ ] **18. Подготовить документацию и материалы ИИ.** README с требованиями, запуском, проверками и демо-доступами; docs с эксплуатацией; исходные экспорты только проектных диалогов, реально использованные настройки/правила/скиллы/MCP. Конспекты не подменяют оригиналы, секреты не попадают в сдачу.
- [ ] **19. Собрать и проверить ZIP.** Код, инфраструктура, README, docs, тесты, seed, исходные диалоги и обвязка, `.git` со всей историей. Архив распакован в отдельную папку, история читается, деплой воспроизводится; исключены реальные секреты, кеши и рабочие тома.
